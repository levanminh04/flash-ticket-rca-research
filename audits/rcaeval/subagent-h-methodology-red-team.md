# Subagent H — Methodology Red Team

**Status:** `COMPLETE`  
**Role:** independent adversarial review for Task B  
**Scope:** pinned RCAEval metadata, seven locally hash-verified raw cases, the completed all-90-case RE2-TT trace audit, and one targeted normal log-bearing RE2-TT case. This report makes no method, algorithm, research-question, or FlashTicket design decision.

## Verdict after attempted falsification

The available evidence does **not** justify rejecting RE2-TT as a trace-plus-metrics, service-level, known-incident-window RCA dataset. It does require strict boundaries that materially narrow what can be claimed:

- The graph is a **literal trace-derived service/operation representation** with resolved parent-to-child trace relations. It is not a `CALLS`, `USES`, messaging, causal-propagation, or resource graph.
- A literal `(serviceName, operationName)` pair is a supported representation. Operation-level root-cause ranking is **NOT EVALUABLE WITH CURRENT GROUND TRUTH**.
- `root_cause_service` supports service-level ranking, not service-level anomaly labels, node-level anomaly F1, affected-node evaluation, or propagation-path evaluation.
- `case`, directory names, `root_cause_service`, `fault`, `root_cause.txt`, and injection-oracle fields are unusable as blind-model features under the policy below.
- RE2-TT candidate services must be derived from visible telemetry. The five injected-service labels are not a candidate universe.

No checkpoint conclusion needs reversal on trace-derived graph constructability or service-level root-cause labels. Three checkpoint statements need correction:

1. **Multimodal join wording:** logs↔metrics is a direct key join at an exact service/container-plus-second bin; logs↔traces and metrics↔traces are only service-plus-time-window joins. None is an event/request-level or causal correlation.
2. **Graph completeness wording:** the full RE2-TT trace subset has 98.45274372% parent resolution overall, but seven cases are below 90% and the low point is 38.54287289%. A resolved relation is evidence; an unresolved reference is not an edge to repair or infer.
3. **Candidate-universe wording:** RE2-TT has five service labels but 20–27 literal trace service names per case. A five-service label-based universe makes Top-5 structurally trivial and is forbidden.

## Precise red-team constraints for the Task-B verdict

### Minimal evidence-supported graph for RE2-TT

```text
ServiceNode = exact trace.serviceName
OperationNode = exact (trace.serviceName, trace.operationName)
SpanParentRelation = (traceID, parentSpanID) -> (traceID, spanID), only when resolved in the same case
ServiceParentChildRelation = parent.serviceName -> child.serviceName, only for resolved cross-service span relations
```

This is supported for all 90 RE2-TT trace files. It has 27 literal service names, 161 literal service-operation pairs across the subset, and 55 observed cross-service relation types. The operation pair is a representation, not a semantic ground-truth target. Unresolved parent references stay unresolved.

### Multimodal classification

| Pair | Final classification | Deterministic rule | Boundary |
|---|---|---|---|
| Metrics ↔ Logs | `DIRECT` at service/container-second aggregation | `logs.timestamp == metrics.time` and exact `logs.container_name == entity(metric column suffix)` | one log can map to several metric series; not a request/event correlation |
| Metrics ↔ Traces | `SERVICE+TIME` | `metrics.time == floor(traces.startTimeMillis / 1000)` and exact literal entity/service equality | no metric trace/span ID |
| Logs ↔ Traces | `SERVICE+TIME` | `logs.timestamp == floor(traces.startTimeMillis / 1000)` and exact literal container/service equality | no log trace/span ID; B2B exact-match scan is 0/0 |

The B2B result is a raw finding for one normal log-bearing RE2-TT case, not a claim that every one of the 89 log-bearing cases has identical log schema or join coverage.

## Result for the main cross-review

The red team finds no hard external blocker to closing Task B. It does find four non-negotiable conditions for a valid RE2-TT pilot assessment: keep labels/oracles/path information out of inputs; derive service candidates from telemetry rather than the injection label set; retain only resolved trace relations without semantic upgrades; and distinguish direct service-second log/metric aggregation from the two approximate trace joins.

The machine-readable classifications and exact counts are in `subagent-h-red-team-findings.json` and `subagent-h-red-team-evidence.json`.
